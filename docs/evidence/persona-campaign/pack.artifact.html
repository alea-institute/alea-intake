EP-INTAKE-PERSONAS-002

Bugs found and FIXED this campaign (deployed to dev)

Pass

Fixed and deployed to Railway alea-intake-dev this campaign:

  • BUG-3 — dev LLM key/model misconfigured; added Railway vars + new ALEA_LLM_PROVIDER/ALEA_LLM_MODEL/ALEA_LLM_API_KEY env overrides, set to gpt-4o-mini per policy 5.
  • BUG-4 — LLM client called with the wrong API shape at every seam (positional messages args; calls to a nonexistent LLMService.json_async that raised AttributeError, silently swallowed).
  • BUG-6 — OpenAI JSON-mode's "contains the word 'json'" requirement was unmet, killing the gap and question-generation stages outright.
  • BUG-7 — extraction prompt never named the schema fields, so pydantic validation rejected every extracted fact (0 facts extracted, forever).
  • BUG-8 — exploration stage ran on 0 facts and fabricated generic claims, then re-ran on every iteration (133 spam claims/persona). Fixed: once-per-run execution + name-based dedupe + no-facts guard.
  • BUG-9 — shared.folio_embeddings was never provisioned (ensure_table never called, no shared schema), so the resolver cascade died at stage 1. Fixed with graceful per-stage degradation. Related startup fix: moved index build off the boot critical path (it was killing the healthcheck / deploys) and batched the upserts (18,325 vectors indexed in 48s).
  • BUG-10 — code assumed a dict contract against folio-python's actual List[OWLClass] return type (build_index, _determine_branch, adjacency traversal).
  • BUG-11 — search_by_label returns (OWLClass, score) tuples, not bare objects; the label-resolution stage crashed on this and silently zeroed ALL IRIs. Also fixed in this pass: issue_spot per-run claim dedupe (was emitting 'Nonpayment of Rent' x3).
  • BUG-5 — downgraded: turned out to be a harness JSON-export misreport, not a pipeline bug.

Meta-finding: three unit test fixtures encoded the wrong contracts (a positional chat_async assertion, dict-shaped classes, a bare-object search_by_label stub) — unit-green, integration-dead. The fixtures matched the code's wrong assumptions, not the real dependency's behavior.

EP-INTAKE-PERSONAS-003

Bugs found, OPEN (next iteration)

Fail
  • BUG-12 — deadline year-anchor: the LLM extracts trigger dates with the wrong year (e.g. 2023-06-15 for a Jun 15, 2026 event) because the prompt gives it no 'today' anchor. computed_date comes back null even for verbatim dates (an Aug 20, 2026 hearing still resolves to 'date unclear'). rule_id/citation are null everywhere — the rules table is never wired through. This is the root cause of the RUB-08/RUB-09 gate failures across all three personas.
  • BUG-13 — FOLIO adjacency exploration spam: roughly 32 of 47 immigration claims are ontology-traversal noise, including a literal 'ZZZ - SANDBOX: UNDER CONSTRUCTION' placeholder concept surfaced as a legal claim. Needs placeholder/deprecated-concept filtering plus a relevance threshold.
  • BUG-14 — duplication cluster: memo claim sections repeated up to 9x, gap questions ~92% duplicates (50 questions generated from ~4 templates), fact-links repeated 8-10x. Gaps/questions/memo assembly lack the dedupe logic claims already got this campaign.
  • BUG-15 — safety_alerts = 0 on a narrative describing grabbing, bruising, and an explicit threat (DV persona). The safety detector is inert.
  • BUG-16 — question_gen silently produced 0 questions for the immigration persona despite 55 open gaps.
  • BUG-17 — memo/run traceability mismatch: memo header shows Matter 98 / Run 20 while run.json shows intake 107 / run 23 — the memo was generated from a stale run.

Plus, not yet bug-numbered: 'No authorities identified' on all 51 landlord-tenant claims (authority/research stage isn't delivering citations); RUB-10 plain-language Flesch-Kincaid grade came back 17-23 vs a ~6 target (the plain-language adapter isn't reaching the output path); the memo leaks pipeline jargon (e.g. 'Practice Area Match 96%'); and a '[URGENT]' flag fires on 30+ items, causing alarm fatigue.
