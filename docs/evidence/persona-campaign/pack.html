A persona UAT campaign surfaced that the app's UI and API scaffolding was complete and unit-tested, but its LLM seams were never wired — every real intake produced an empty analysis, invisible to the passing test suite. All four defects are now fixed, tested, and deployed. One external blocker remains before the findings can be validated live.

02Findings & fixes

Analysis pipeline was inert EP-INTAKE-BUG-1 · critical Fixed

Fact extraction was never invoked by any ingestion path (text, document, or voice), so the analysis orchestrator always loaded zero facts → 0 claims, 0 gaps, empty memo. It passed 1045 unit tests because extraction was only ever tested in isolation; the ingestion→analysis seam had no end-to-end test.

Fixed: a fact-extraction backfill at analysis-trigger time — one idempotent wiring point covering every modality. Validated live: the pipeline now finds and processes messages.

Conversation was a stub EP-INTAKE-BUG-2 · high Fixed

The intake chatbot never called the LLM — it returned the same canned sentence to every message ("Thank you for sharing that…").

Fixed: added a shared LLMService.acomplete() text helper and wired the conversational response through it, with a graceful fallback.

Plain-language memo was a no-op EP-INTAKE-RUB-10 · high Fixed

The reading-level adapter returned text unchanged, so consumer memos stayed at attorney reading level — failing the accessibility bar for stressed, mixed-literacy clients.

Fixed: the adapter now rewrites prose at the profile's reading level (6th–8th grade), preserving legal citations verbatim.

Deadline / SOL detection built EP-INTAKE-II.3.1 · feature Shipped

The highest-stakes consumer value — missed deadlines end cases — didn't exist (deadlines were hardcoded empty). Now a "detect + hedge" engine extracts time-sensitive events, computes dates from a cited, human-reviewed Minnesota rule table, and surfaces them in a prominent, hedged memo section.

Verified deterministically against every persona's planted deadline (e.g. served Jun 15 → response due Jul 15; asylum one-year window flagged lapsed).

Dev server's LLM key is non-functional EP-INTAKE-BUG-3 · blocker Open

Fixing the wiring above exposed that the dev server's LLM provider itself doesn't work — invisible until now because every LLM path was stubbed, so the credential was never exercised. This blocks live validation of all of the above. It needs Railway access to resolve (see below).

03The one thing in the way

Railway credentials → dev LLM key

Everything is fixed and deployed; the retest → judge → close loop just needs a working LLM on the dev server. The Railway CLI is de-authenticated and the token isn't in an agent-readable location (twin-secrets is SOPS-encrypted and guarded). Either path unblocks it:

  • Re-auth Railway: script -qfc "railway login --browserless" /tmp/pair.log → open the printed URL → confirm.
  • Or pull a token yourself: cd twin-secrets && sops -d secrets.enc.yaml | grep -i railway.

04What happens on unblock

  1. Set the LLM key + switch dev to a cheap model, redeploy. Fast restart, no rebuild.
  2. Retest all three personas end-to-end against the live server.
  3. Judge vs the locked rubric — deterministic FOLIO checks + the hidden answer-key oracle.
  4. Populate this evidence pack with per-persona scores, then close v1.0 UAT.
  5. Reconcile the stale roadmap against authoritative project state. Ungated — can run anytime.
