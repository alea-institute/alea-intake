    **useNarrativeData.ts** -- Critical algorithm for overlapping annotation resolution (Pitfall 4):

    Input: VisualizationData, filter state from store

    Output:
    ```typescript
    interface NarrativeData {
      messageTexts: MessageAnnotation[]
      legend: LegendEntry[]
      claimColorMap: Map<number, string>
    }
    interface MessageAnnotation {
      messageId: number
      text: string
      senderType: string
      segments: TextSegment[]
    }
    interface TextSegment {
      start: number
      end: number
      text: string
      claimIds: number[]    // empty = plain text
      factIds: number[]
      colors: string[]      // corresponding palette colors
      isAnnotated: boolean
    }
    interface LegendEntry {
      claimId: number
      claimName: string
      color: string
    }
    ```

    Algorithm for building segments (CRITICAL -- avoids Pitfall 4 of invalid nested HTML):
    1. For each message, collect all source_spans that reference that message_id
    2. For each span, look up fact_id -> find mappings -> get claim_ids for that fact
    3. Build a list of "events" at each character position boundary: (position, 'start'|'end', claimId, factId)
    4. Sort events by position, then 'start' before 'end'
    5. Sweep through events tracking an "active claims" set. At each position change, emit a segment with the current set of active claims
    6. Segments with no active claims = plain text. Segments with active claims = annotated
    7. Assign colors to claims: stable mapping using claim index into CATEGORICAL_PALETTE (modulo palette length)
    8. Apply filters: if a claim is not in the active layer filter or claim filter, exclude its annotations

    This sweep-line approach ensures every segment has a flat, non-overlapping representation with a list of contributing claims -- no nested/crossing HTML elements.

    Memoize with useMemo keyed on data + filter state.
