# Plan 06-01: Research Tool Adapter Framework and Citation Verification

## Objective

Build the pluggable legal research tool infrastructure: abstract adapter pattern, tool registry, DB models for authorities and research results, CourtListener as first concrete adapter, and citation verification service.

## Context

@backend/app/services/folio/concept_resolver.py (concept resolution pattern to follow)
@backend/app/services/llm_service.py (service pattern to follow)
@backend/app/models/folio_concepts.py (tenant model pattern to follow)
@backend/app/config.py (settings pattern)

## Tasks

<task id="1" type="auto">
<name>Research DB models, schemas, and config settings</name>
<description>
Create tenant-scoped SQLAlchemy models for research infrastructure:
- Authority: stores legal authorities (cases, statutes, regulations) with FOLIO IRI, citation string, jurisdiction, authority_type, source_tool, verified flag, verification_source, and full_text excerpt
- ResearchResult: links an intake+claim to authorities found, with query text, tool used, and relevance score
- ResearchToolConfig: per-org configuration of which research tools are available, with API keys (encrypted) and enabled flag
- CitationVerification: records each verification attempt with source, result, timestamp

Add config settings for research tool defaults (courtlistener_base_url, research_timeout_seconds, max_results_per_query).

Create Pydantic response/request schemas for the research API.
</description>

  - Models registered in backend/app/models/__init__.py
  - Config settings added to backend/app/config.py
  - Pydantic schemas exist in backend/app/schemas/research.py
  - Tests pass for model creation
</done>
</task>

<task id="2" type="auto">
<name>Research adapter ABC, registry, and CourtListener adapter</name>
<description>
Create the pluggable research tool framework:
- ResearchAdapter ABC with: adapter_name, discover(query) -> list[ResearchResult], fetch_authority(citation) -> Authority|None, verify_citation(citation) -> bool
- ResearchQuery dataclass with claim_iri, jurisdiction, query_text, authority_types filter, max_results
- ResearchResult dataclass with authority data and relevance score
- ResearchToolRegistry singleton that manages adapter instances, discovers available tools for an org, dispatches queries to all configured adapters, and merges results
- CourtListenerAdapter implementing ResearchAdapter using httpx async HTTP client against CourtListener v4 REST API (search opinions, fetch by citation)
- Citation verification service that checks LLM-suggested citations against configured research tools

Wire registry into app lifespan. Register CourtListener as default adapter.
</description>
<done>
  - ResearchAdapter ABC exists with discover/fetch/verify methods
  - ResearchToolRegistry singleton manages adapters
  - CourtListenerAdapter queries CourtListener REST API
  - CitationVerifier checks citations against registered tools
  - Registry wired into app lifespan
  - Tests pass for adapter registration, query dispatch, and verification flow
</done>
</task>

<task id="3" type="auto">
<name>Research API endpoints and test suite</name>
<description>
Create research router with endpoints:
- POST /api/research/query: Query configured research tools for a claim+jurisdiction, returns merged results
- POST /api/research/verify: Verify a citation against configured tools, returns verification result with source
- GET /api/research/tools: List research tools configured for the current org
- POST /api/research/tools: Configure a research tool for the org (admin only)

Write comprehensive test suite covering:
- Model creation and relationships
- Adapter registration and query dispatch
- CourtListener adapter with mocked HTTP responses
- Citation verification with mock adapter
- API endpoint tests with auth
- Error handling (tool not configured, API timeout, invalid citation)
</description>
<done>

  - All 4 endpoints functional
  - Test suite covers models, adapters, registry, verification, and API endpoints
  - All tests pass
</done>
</task>
