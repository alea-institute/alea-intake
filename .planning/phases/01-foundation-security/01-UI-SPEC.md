# Phase 1 -- UI Design Contract

> Visual and interaction contract for Phase 1: Foundation & Security.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Scope: Backend-Only

Phase 1 is explicitly backend-only (per RESEARCH.md). No frontend screens, components, or interactions are built in this phase. The frontend directory is scaffolded as an empty pnpm monorepo shell with Vite + React + TypeScript + Tailwind configured, but no pages or components are created.

All user-facing flows in this phase (authentication, consent capture, audit log review, deletion cascade preview) are **API endpoints only**. Their UIs are built in Phase 8 (Frontend Application).

This UI-SPEC therefore serves two purposes:
1. Documenting that Phase 1 has no UI deliverables to verify
2. Establishing foundational design tokens in the Tailwind config scaffold so Phase 8 inherits a coherent design system from day one

## Color

Not applicable -- no UI is built in Phase 1.

Recommended palette direction for Phase 8. Legal intake demands trust, clarity, and accessibility (WCAG 2.1 AA minimum):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | TBD in Phase 8 | Background, surfaces |
| Secondary (30%) | TBD in Phase 8 | Cards, sidebar, nav |
| Accent (10%) | TBD in Phase 8 | Primary CTAs, active consent toggles, progress indicators |
| Destructive | TBD in Phase 8 | Delete account, revoke consent, cascade deletion confirmation |

Accent reserved for: primary action buttons (consent grant, login), active/selected states in consent toggles, progress step indicators in analysis pipeline.

**Design direction note:** The legal domain calls for a palette that communicates institutional trust without being sterile. Avoid generic SaaS purple-blue gradients. Consider deep navy, warm stone, or forest green palettes that evoke law library / courtroom gravitas while remaining accessible.

## Copywriting Contract

Phase 1 defines API responses only. The following copy is for API error messages and response bodies -- not rendered UI. Frontend copy is defined in Phase 8.

| Element | Copy |
|---------|------|
| Auth: login success | `{ "message": "Authentication successful" }` |
| Auth: invalid credentials | `{ "detail": "Invalid email or password" }` |
| Auth: token expired | `{ "detail": "Token has expired. Please log in again." }` |
| Auth: insufficient role | `{ "detail": "Insufficient permissions for this action" }` |
| Consent: not granted | `{ "detail": "Consent required before AI processing can begin" }` |
| Consent: revoked | `{ "detail": "Consent has been revoked. AI processing is paused." }` |
| Deletion: preview | `{ "preview": { "records_affected": N, "categories": [...] } }` |
| Deletion: confirmed | `{ "message": "Deletion complete. N records removed." }` |
| Deletion: requires confirmation | `{ "detail": "Deletion requires explicit confirmation. Use the confirm endpoint." }` |
| Tenant: isolation violation | `{ "detail": "Access denied" }` (generic -- never leak tenant info) |
| Encryption: key unavailable | `{ "detail": "Service temporarily unavailable" }` (generic -- never expose crypto state) |

**Destructive actions in Phase 1 APIs:**
- **Right-to-delete cascade**: Requires admin confirmation via separate POST to `/confirm-delete` endpoint with preview hash. No single-request deletion.
- **Consent revocation**: Immediate effect, no confirmation required (consumer right).
- **Account deletion**: Triggers right-to-delete cascade (same flow).

## Frontend Scaffold Contract

Phase 1 scaffolds the following frontend structure with no components:

```
frontend/
  package.json          # React, Vite, TypeScript, Tailwind dependencies
  vite.config.ts        # Standard Vite config
  tsconfig.json         # Strict TypeScript config
  tailwind.config.ts    # Design tokens pre-seeded (spacing scale above)
  postcss.config.js     # Tailwind + autoprefixer
  src/
    main.tsx            # React entry point (renders placeholder)
    App.tsx             # Placeholder component
    index.css           # Tailwind directives only
```

This structure ensures Phase 8 can immediately begin building components without re-scaffolding. No shadcn initialization occurs in Phase 1.
