# 13-03 — Practice-area chip-row above the welcome card

## Goal

Render a chip-row at the top of the intake landing/welcome screen. "Generic" is the always-available default; selecting a practice chip (a) updates the welcome card copy to that practice's `welcome_message_*`, (b) stores the selected practice id in chat state, and (c) includes `practice_area_id` in the session-create payload when the user starts the conversation.

## Discovery first

Before writing UI code, run:
- `rg -n "welcome|Welcome" frontend/src/features/chat/ -t tsx -t ts | head`
- `cat frontend/src/features/chat/ChatPage.tsx | head -120`
- `cat frontend/src/features/chat/store.ts | head -120`
- `cat frontend/src/features/chat/api.ts`

This pins down the exact spots to splice the chip-row in and where session creation happens.

## Files to create

- `frontend/src/features/chat/components/PracticeAreaChips.tsx`
  - Props: `selectedId: string | null`, `onSelect: (id: string | null) => void`
  - Fetches practice areas via a hook (see below) and renders:
    - A `Generic` chip first (mapped to `null` selection — represents "no practice bound")
    - Then one chip per fetched practice, sorted by `display_name`
  - Visual: horizontal scrollable row, pill chips, clear selected state (filled vs outlined), accessible (ARIA `role="radiogroup"`, each chip `role="radio"` with `aria-checked`)
  - Keyboard: arrow keys move focus between chips, Enter/Space selects (use `role="radio"` semantics)
  - If a selected practice has a non-null `disclaimer`, render it inline below the chip-row in a muted callout style — matters for sensitive practices added live during the demo
- `frontend/src/features/chat/hooks/usePracticeAreas.ts`
  - Queries `GET /api/practice-areas` (use whatever query pattern this project already uses — likely react-query or a custom hook; check `frontend/src/features/chat/api.ts`)
  - Returns `{ practiceAreas, isLoading, error }`
  - Cache for the lifetime of the page; no need for revalidation during a single intake session
- `frontend/src/features/chat/components/PracticeAreaChips.test.tsx`
  - Renders the Generic chip plus mocked practices; clicking one fires `onSelect` with the right id; clicking Generic fires `onSelect(null)`
  - Disclaimer renders only when present
  - Keyboard: arrow keys move the focused chip; Enter selects

## Files to modify

- `frontend/src/features/chat/store.ts`
  - Add `practiceAreaId: string | null` to chat state with action `setPracticeArea(id: string | null)`
  - Default: `null`
- `frontend/src/features/chat/api.ts`
  - Add `fetchPracticeAreas()` returning `{ practice_areas: [...] }` typed
  - Update `createSession()` (or whatever creates a session) to accept and forward `practice_area_id`
- `frontend/src/features/chat/types.ts`
  - Add `PracticeArea = { id: string; display_name: string; disclaimer: string | null }`
- `frontend/src/features/chat/ChatPage.tsx` (or wherever the welcome card lives — verify during discovery)
  - Render `<PracticeAreaChips selectedId={practiceAreaId} onSelect={setPracticeArea} />` above the welcome card
  - When the user starts the conversation, pass `practiceAreaId` to `createSession`
  - When `practiceAreaId` changes, swap the welcome message copy to the selected practice's `welcome_message_consumer` (or `welcome_message_professional` based on the existing role flag) — fall back to the existing generic welcome when `practiceAreaId === null`

## Visual / UX guidance (frontend-design skill applies)

- **No generic chip styling** — match the existing visual language of the intake. Lookup: ALEA intake uses [check `frontend/src/styles/`]; lean on existing CSS variables, not hard-coded colors.
- **Scale:** the Generic chip is visually equal to the practice chips, not subordinated. It's a real choice, not a placeholder.
- **Active state must be unmistakable** at projector distance — bold filled background, subtle scale-up (`transform: scale(1.02)`), and an accent color from the existing theme. Audience-facing: clarity over subtlety.
- **Loading state:** skeleton chips, not a spinner — keeps layout stable when the audience first lands on the page.
- **Failure state:** if `/api/practice-areas` errors, hide the row entirely and fall back to the existing generic intake. Never block the user from starting a conversation because chips failed to load.
