# 13-05 — Dry run, runbook, and confidence-tested sample practices

## Goal

De-risk the live talk. Run the full `discuss → plan → execute → push → deploy` loop end-to-end on at least two non-PI practice areas before the talk so Damien knows the audience-driven flow actually completes, and produce a tight runbook with the exact commands and talking points.

## Why this plan exists

Process is the demo's primary "wow moment." If anything in the live loop has surprising friction (slow LLM, flaky test, Railway redeploy timing), Damien needs to know about it now — not on stage.

## Step 1 — Dry-run candidate practices

Pick **two** plausible audience suggestions and run the full flow on each in a throwaway local branch:

- **Immigration law** — distinctive intake (visa type, USCIS deadlines, country of origin, removal proceedings, language), no overlap with PI.
- **Patent prosecution** — sharply technical (invention disclosure, prior art, inventors, claim types, USPTO bar dates).

For each:
1. Branch off `demo/practice-customization`: `git checkout -b dryrun/<practice>`
2. Run `/gsd-discuss-phase` answering "yes, add a new practice area: <name>" — observe how many questions Claude asks (target: ≤5 to keep stage time short)
3. Run `/gsd-plan-phase` — confirm it produces a single small plan that just adds a YAML
4. Run `/gsd-execute-phase` — confirm it generates a sensible `<practice>.yaml` and runs loader tests
5. Time the loop start-to-finish (target: **< 8 minutes**). Record actual time.
6. **Don't commit** — `git checkout demo/practice-customization && git branch -D dryrun/<practice>` after each. The point is rehearsal, not pre-baking practices that should look spontaneous on stage.

**If a dry run takes > 12 minutes:** prune the discuss-phase prompts. Edit the practice-area discuss flow (or just decide to bypass discuss-phase and go straight to plan-phase on stage) — note the choice in the runbook.

## Step 2 — Pre-baked emergency YAMLs

Generate the three YAMLs (immigration, patent, family law) and stash them in `.planning/phases/13-practice-area-customization-demo/emergency-configs/` — **not committed to the demo branch**, just available as paste fodder if the live loop dies on stage and Damien needs to manually drop in a config.

Each emergency YAML must:
- Validate against the 13-01 schema
- Have a non-trivial `system_prompt` and ≥6 `key_topics`
- Include a `disclaimer` field for family law (sensitive practice — spousal abuse screening note)

## Step 3 — Write the runbook

Create `.planning/phases/13-practice-area-customization-demo/DEMO-RUNBOOK.md` with:

**Pre-talk checklist (T-30 min):**
- [ ] Demo URL live: `curl $DEMO_URL/health`
- [ ] PI session works in browser
- [ ] Claude Code (web) connected to Linux box; terminal sized for projector
- [ ] Working directory on `demo/practice-customization`
- [ ] `git status` clean, `git pull` if Railway-side changes happened
- [ ] Screen brightness up, font size up (terminal + browser)
- [ ] Backup browser tab pinned to demo URL
- [ ] `emergency-configs/` directory open in a side editor pane

**On-stage script (rough beats — Damien adapts live):**
1. **Hook (30s):** "I'm going to build a custom legal intake for whatever practice area you shout out. Live."
2. **Audience pick:** take a suggestion. Repeat it back. ("Immigration. OK.")
3. **Show baseline:** flip to the deployed app, click around the Generic intake, then PI — show the difference in welcome copy + follow-up tone.
4. **Run the loop:**
   - `/gsd-discuss-phase` "Add a new practice area: immigration"
   - Answer questions on stage (Claude prompts; Damien answers in plain English)
   - `/gsd-plan-phase`
   - `/gsd-execute-phase`
   - `git push`
5. **Bridge while Railway deploys (~60–90s):** explain what just happened — talk about the YAML schema, why config-driven beats hand-coded, why the LLM system prompt is the leverage point.
6. **Reveal:** refresh browser, click the new chip, walk into a tailored intake. Send one realistic message ("My visa expires in 30 days and I just got laid off"), show the practice-aware follow-up.
7. **Land it (30s):** "That's not a static demo — it's the system writing itself. Anyone in this room could do this for their own practice."

**Failure modes & responses:**
- **Railway redeploy slow / stuck:** keep talking through architecture; if it doesn't come up in 3 min, switch to PI and explain "the same mechanism, different config." Don't apologize — own the explanation.
- **Generated YAML fails loader tests:** `git reset --hard HEAD~1`, paste the matching emergency config, commit, push.
- **LLM doesn't follow practice prompt convincingly:** good. That's a talking point about why eval matters — pivot to "and this is exactly the kind of regression we'd catch with…"
- **Audience suggests something sensitive (mass torts class action, criminal defense for accused):** use the family-law-style disclaimer pattern; emphasize this is intake, not advice.
