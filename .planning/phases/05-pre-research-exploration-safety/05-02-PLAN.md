<objective>
Three-layer exploration engine and ExploreStage orchestrator integration.

Purpose: Implements the core exploration logic that runs between issue-spotting and research in every analysis iteration. The engine uses a hybrid parallel approach (D-05): a cheap LLM wide-net scan runs concurrently with a sequential FOLIO adjacency -> protocol matching -> expensive LLM pipeline. Results are deduplicated via ConceptResolver to FOLIO IRIs. Multi-round stability detection (D-06) ensures thorough exploration without runaway loops. Discovered issues become new AnalysisClaim records that feed into the research stage.

Output: ExplorationEngine (three-layer parallel with dedup), four layer implementations, ExploreStage (orchestrator-compatible), updated orchestrator STAGES list.
</objective>

    **Layer Implementations** (backend/app/services/exploration/layers.py):
    Four async functions, each returning list[ExplorationResult]:

    1. `async def layer_folio_adjacency(folio, existing_claims, config) -> list[ExplorationResult]`:
       For each claim with a folio_iri, call `discover_adjacent_concepts(folio, claim.folio_iri, AdjacencyConfig(max_depth=2))`. Convert adjacent concept nodes into ExplorationResult objects with source_layer="folio_adjacency", confidence based on graph distance (depth 1 = 0.7, depth 2 = 0.5). Skip if folio is None (graceful degradation). Return deduplicated results (don't re-discover existing claims).

    2. `async def layer_protocol_match(active_protocols, facts_text, existing_results=None) -> list[ExplorationResult]`:
       For each active protocol, check if trigger_conditions match against the combined facts text. Use the same keyword/regex matching as TriggerMatcher but return the protocol's questions and issue descriptions as ExplorationResult objects with source_layer="protocol_match", protocol_id set. This is the layer that surfaces screening protocol insights during exploration.

    3. `async def layer_cheap_llm(llm_service, facts_text, existing_claims, org_config) -> list[ExplorationResult]`:
       Build a prompt with all facts and existing claims asking for "additional legal issues a consumer might not know to mention." Use the cheap LLM (ExplorationConfig.cheap_llm_provider/model or org default). Parse structured JSON response. Return ExplorationResult objects with source_layer="cheap_llm". If LLM unavailable, return empty list (graceful degradation per existing pattern).

    4. `async def layer_expensive_llm(llm_service, facts_text, existing_claims, folio_context, protocol_context, org_config) -> list[ExplorationResult]`:
       Build a richer prompt incorporating FOLIO adjacency results and protocol match results from prior sequential layers. Ask the expensive LLM to reason about legal issue connections and identify issues the cheap LLM and ontology might have missed. Return ExplorationResult objects with source_layer="expensive_llm".

    **ExplorationEngine** (backend/app/services/exploration/engine.py):
    Core class implementing D-05 hybrid parallel and D-06 multi-round stability:

    - `__init__(self, folio, llm_service, embedding_service, db_session, org_config, protocol_service)`: Store dependencies. Parse ExplorationConfig from org_config.
    - `async def explore(self, run, iteration, claims, facts) -> ExplorationStageResult`:
      Main entry point. Build facts_text from facts list. Load active protocols via protocol_service.get_active_protocols(). Loop through rounds:
      ```
      for round_num in range(1, config.max_rounds + 1):
          round_result = await self._run_exploration_round(context)
          all_rounds.append(round_result)
          if round_num >= config.min_rounds and round_result.is_stable:
              break
      ```
      After all rounds, collect new issues and return ExplorationStageResult.

    - `async def _run_exploration_round(self, context) -> ExplorationRoundResult`:
      Per D-05 hybrid parallel:
      ```python
      # Branch A: Cheap LLM (fast, broad)
      cheap_task = layer_cheap_llm(self._llm, context.facts_text, context.known_claims, self._org_config)

      # Branch B: Sequential precision pipeline
      async def _sequential():
          folio_results = await layer_folio_adjacency(self._folio, context.known_claims, context.config)
          protocol_results = await layer_protocol_match(context.active_protocols, context.facts_text, folio_results)
          expensive_results = await layer_expensive_llm(
              self._llm, context.facts_text, context.known_claims,
              folio_results, protocol_results, self._org_config
          )
          return folio_results + protocol_results + expensive_results

      cheap_results, sequential_results = await asyncio.gather(cheap_task, _sequential())
      ```
      Merge and deduplicate via `_deduplicate_results`. Filter by exploration_confidence_threshold. Compute new_issues_count (results not in known_claims). is_stable = new_issues_count <= config.stability_threshold.

    - `async def _deduplicate_results(self, all_results) -> list[ExplorationResult]`:
      Per RESEARCH.md deduplication algorithm: Group by folio_iri (keep highest confidence). For unresolved results, try ConceptResolver. Keep truly unresolvable results as-is. Use the embedding_service if available for ConceptResolver calls.

    **ExploreStage** (backend/app/services/analysis/stages/explore.py):
    Follow the IssueSpotStage pattern exactly:

    ```python
    class ExploreStage:
        def __init__(
            self,
            llm_service: LLMService,
            db_session: AsyncSession,
            folio: FOLIO | None = None,
            embedding_service: EmbeddingService | None = None,
            org_config: dict | None = None,
        ) -> None:
            self._llm = llm_service
            self._session = db_session
            self._folio = folio
            self._embedding_service = embedding_service
            self._org_config = org_config or {}

        async def execute(
            self,
            run: AnalysisRun,
            iteration: AnalysisIteration,
            claims: list[AnalysisClaim],
            facts: list[ExtractedFact],
        ) -> dict:
    ```

    Inside execute:
    1. Parse ExplorationConfig from org_config (same pattern as AnalysisConfig parsing in orchestrator).
    2. Create ProtocolService with db_session. Call get_active_protocols().
    3. Create ExplorationEngine with all dependencies.
    4. Call `engine.explore(run, iteration, claims, facts)` to get ExplorationStageResult.
    5. For each new_claim in result.new_claims, create AnalysisClaim record:
       - iteration_id=iteration.id
       - claim_name=claim["claim_name"]
       - claim_type="discovered" (per EXPLORE-10 -- these are issues the consumer didn't mention)
       - folio_iri=claim.get("folio_iri")
       - confidence=claim["confidence"]
       - is_potential=True (per Phase 04 D-08)
       - rationale=claim.get("rationale", f"Discovered via {claim['source_layer']} exploration")
       - metadata_json={"source_layer": claim["source_layer"], "exploration_round": round_num}
    6. Add question_transparency flag from ExplorationConfig to result for downstream use per EXPLORE-06.
    7. Return result dict for orchestrator (new_claims count, triggered_protocols, rounds_completed, total_new_issues).
